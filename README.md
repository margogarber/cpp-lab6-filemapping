# Лабораторна робота №6 — «Клієнт-серверна архітектура додатку. Метод комунікації: відображення (проекція) файлу в пам'ять»

**Виконала:** Гарбєр Маргарита Олександрівна, група ІА-з41
**Варіант:** 1 (|4 − 5|, де 4 — варіант лабораторної роботи «Сокети», 5 — «Поштові скриньки»)

Програмний комплекс із трьох віконних Win32-додатків мовою C++, які обмінюються даними через
іменований об'єкт відображення файлу в пам'ять (file mapping) `Local\lab6_garber_map`:

| Додаток | Призначення |
|---|---|
| `Server.exe` | створює filemapping, читає його за командою меню або автоматично за подією, відображає отримані дані, закриває filemapping |
| `Client1.exe` | висота смуги меню, наявність миші, ширина екрану |
| `Client2.exe` | ширина та висота іконки, ширина вертикальної смуги прокрутки, глибина кольору |

## Структура

```
src/common.h         спільні функції та структура спільної пам'яті, імена об'єктів ядра
src/server.cpp       сервер FileMapping
src/client_core.*    спільна логіка клієнтів (формування повідомлення і запис у проекцію)
src/client1.cpp      дані Клієнта 1
src/client2.cpp      дані Клієнта 2
```

## Завдання варіанту 1

| Клієнт 1 | Клієнт 2 |
|---|---|
| ширина смуги меню (`GetSystemMetrics(SM_CYMENU)`) | ширина та висота іконки (`SM_CXICON`, `SM_CYICON`) |
| наявність миші (`GetSystemMetrics(SM_MOUSEPRESENT)`) | ширина вертикальної смуги прокрутки (`SM_CXVSCROLL`) |
| ширина екрану (`GetDeviceCaps(hdc, HORZRES)`) | глибина кольору (`GetDeviceCaps(hdc, BITSPIXEL)`) |

Константа `SM_CYMENU` повертає висоту однорядкової смуги меню, тому Клієнт 1 додатково надсилає фактичний
розмір смуги меню свого вікна, отриманий через `GetMenuBarInfo`.

## Обмін даними

Спільна пам'ять (8192 байт) містить заголовок (ознака, лічильник повідомлень, PID і назва відправника, довжина)
та текст повідомлення у кодуванні UTF-8.

**Сервер**
- «FileMapping → Створити» — `CreateFileMapping(INVALID_HANDLE_VALUE, …, PAGE_READWRITE, …)` без фізичного файлу,
  а також іменовані м'ютекс і подія з автоскиданням;
- «FileMapping → Прочитати» — `MapViewOfFile`, читання під м'ютексом, `UnmapViewOfFile`; сервер визначає, чи є нові дані
  і чи не було пропущених (перезаписаних) повідомлень;
- «FileMapping → Закрити» — `CloseHandle` для проекції та об'єктів синхронізації;
- повідомлення про помилку, якщо проекцію вже створив інший екземпляр сервера.

**Клієнти**
- повідомлення за замовчуванням із поточними значеннями; текст можна змінити перед надсиланням;
- `OpenFileMapping` → `MapViewOfFile` → запис під м'ютексом → `SetEvent` → `UnmapViewOfFile` → `CloseHandle`;
- повідомлення про помилку, якщо сервер не запущено або filemapping закрито.

**Завдання «з зірочкою»** — автоматичне виявлення змін: після увімкнення «Автоматичне відстеження змін» сервер
запускає потік-спостерігач, який чекає на подію `Local\lab6_garber_changed` (`WaitForMultipleObjects`) і повідомляє
головне вікно; вміст проекції читається й відображається без натискання «Прочитати». Доступ до спільної пам'яті
впорядковує м'ютекс `Local\lab6_garber_mutex`.

## Вимоги

- Windows 10/11 (x64 або ARM64)
- Visual Studio 2019/2022/2026 з компонентом «Desktop development with C++» **або** MinGW-w64 (g++)

## Збірка

**Developer PowerShell / Developer Command Prompt for VS (MSVC):**
```
.\build_msvc.bat
```

**CMake:**
```
cmake -S . -B build
cmake --build build --config Release
```

**MinGW-w64:**
```
build_mingw.bat
```

## Запуск

1. `build\Server.exe` → «FileMapping → Створити FileMapping (Start)».
2. `build\Client1.exe`, `build\Client2.exe` → «Надіслати у FileMapping».
3. На сервері — «FileMapping → Прочитати FileMapping (Read)» або увімкнути «Автоматичне відстеження змін».

Усі додатки мають працювати в одному сеансі Windows на одному комп'ютері.
